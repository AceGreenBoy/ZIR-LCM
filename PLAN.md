# План реализации сервера (lcm)

Рабочий план. Спецификация — `ARCHITECTURE.md`, требования к прошивке — `FIRMWARE_REQUIREMENTS.md`.
Код сервера — каталог `lcm/`.

## Цель MVP

1. Прошивку **нельзя установить на незарегистрированное устройство**: сервер отдаёт `app.bin`
   только зарегистрированным устройствам, зашифрованным ключом `K_ota` этого устройства, и
   подписанным ключом RSA-3072.
2. Разработка прошивки и веб-морды может идти дальше: есть реальный сервер, на котором можно
   зарегистрировать прибор, загрузить сборку, выпустить релиз и получить его на прибор по OTA.
   Есть симулятор устройства, чтобы проверять сервер без железа.

## Что входит в MVP, а что нет

| В MVP | После MVP |
|---|---|
| Ключи сервера, мастер-ключ, `lcmctl` | Сборщик из GitHub, webhook |
| Пользователи, роли, вход с TOTP, аудит | Вход инженера и токены (`/eng/*`) |
| Профили железа | Телеметрия, core dump, аномалии, уведомления |
| Регистрация по коду, подписанный конфиг | Изменение конфига из инженерного меню |
| Аутентификация устройства | Пакет bootstrap для производителя (zip + скрипт) |
| **Загрузка сборок вручную** (`app.bin` + `app.elf` из PlatformIO, `www.tar`), проверка описания и флага dev, подпись | Отзыв пользователей, восстановление, отчёты для `admin` |
| Релизы, каналы `beta`/`stable`, критические, закрепление, назначение версии | Бэкапы, мониторинг |
| `GET /update`, манифест, шифрование под устройство, выдача `www`, `.zwww`, отчёт | |
| `POST /web-password` | |
| Простая админка (htmx) для всего выше | |
| Симулятор устройства `devicesim` | |
| Docker-образ и compose за Traefik | |

Сборки в MVP разработчик делает сам в PlatformIO (`esp32dev_release` + профиль) и загружает в админку.
Сервер всё равно проверяет описание образа и подписывает его сам: ключ подписи не покидает сервер.

## Отличия реализации от ARCHITECTURE.md

- Админка — серверные шаблоны и обычные формы, без htmx (можно добавить, когда понадобится).
- Доменная логика — один пакет `internal/core` вместо отдельных пакетов на модуль; `sqlc` не используется.
- Регистрация: статус запрашивается `GET` с подписью в заголовке `X-Zir-Sig` (единая схема подписи
  запросов, `DEVICE_PROTOCOL.md`).
- Устройство сравнивается с релизами по версии **установленного релиза** (`release_id` в сессии),
  а не прошивки: иначе релиз, где поменялась только веб-морда, предлагался бы бесконечно.
- Версия прошивки в релизе может отличаться от версии релиза (релиз только с новой веб-мордой).
- `/api/v1` — не полный Admin API из раздела 8, а только API для `lcmctl push-dev` и
  `lcmctl push-bootstrap` по токену. Остальное — формы админки за TOTP.
- Админка без JS, кроме страницы «Прошивка USB» (`static/flash.js`): Web Serial есть только в браузере.
- Bootstrap не подписывается сервером и хранится одним образом с 0x0, а не тремя файлами: на L0
  загрузчик ROM подпись не проверяет, а сам bootstrap проверяет подпись рабочей прошивки. Вместо
  zip с `flash.sh` (раздел 10) — прошивка из браузера и скачивание `bootstrap.bin` из «Збірки».

## После MVP (по приоритету)

1. Вход инженера (`/eng/login`, токены, `confirm`) — нужен, чтобы в боевой сборке был инженерный режим.
2. Управление пользователями в админке, коды восстановления TOTP.
3. Телеметрия, core dump, аномалии в админке, уведомления по e-mail.
4. Изменение конфига из инженерного меню (`config/request`, `config/relay`).
5. Сборщик из GitHub (`builder`), webhook.
6. Пакет bootstrap для производителя (zip + `flash.sh`) — если понадобится прошивка без браузера;
   пока её заменяет «Прошивка USB».
7. Бэкапы, мониторинг.

## Что нужно от прошивки, чтобы MVP заработал на железе

Сервер не зависит от этого, но без этого прибор не сможет работать с сервером:
1. `zir_custom_desc_t` (FIRMWARE_REQUIREMENTS 6.4) и сборка под профиль.
2. Публичные ключи сервера из `lcmctl export-pubkeys`.
3. Bootstrap или временный режим регистрации в рабочей прошивке.
4. Клиент `/dev/v1`: auth, update, OTA с `esp_encrypted_img`, `www.tar`.
5. Подписанные приложения (`CONFIG_SECURE_SIGNED_APPS_NO_SECURE_BOOT`) — первым шагом прошить
   по USB образ, подписанный сервером (`lcmctl sign-app` или скачивание из админки).

## Решения по ходу реализации

- Go 1.26 (последний), PostgreSQL 16.
- Тесты совместимости с инструментами Espressif запускаются, если доступен Python с `cryptography`
  (переменная `ZIR_COMPAT_PYTHON`), иначе пропускаются.
